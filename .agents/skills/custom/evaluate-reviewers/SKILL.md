# Evaluate reviewers

Establish what the finite evaluation can support, then preserve enough evidence
for another person to challenge its conclusions. Apply the target repository's
contracts, verification policy and human decision boundaries. Existing task
choices control case counts, reviewer roles/models, resources and retry scope.

Apply [efficient ticket development](../../../../docs/agents/review-records.md#prepare-review-and-repair)
when preparing or correcting the evaluation. Resolve local source/capture failures
before dispatch, investigate repeated causes and preserve complete final-corpus
evaluation and independent implementation reviews where required.

1. **Bound the claim.** Identify the proposed reviewer guidance, source contracts,
   required concerns, acceptable controls, relevant axes and success conditions.
   Establish authorized stages and retry/resource limits from the task; resolve
   consequential missing choices before assignments. A preparation-only request
   ends with a reviewable packet or explicit gaps, without reviewer dispatch.
2. **Verify ground truth before freezing.** Trace every case against its actual
   contract, accepted inputs, callers, writers and observable failures. Preflight
   nominal controls at concrete risks using real behavior where it matters.
   Assumptions need contract support or enforced validation; a proposed control
   that fails its contract is an invalid control, not reviewer overreach. Preserve
   its source and counterexample, explain the gap and repair only within scope.
   Choose cases by distinct risks rather than a Cartesian platform/input matrix.
   Historical control failures included nested aliases, parser limits, filesystem
   byte/newline decoding, abbreviated Git refs and ambient routing/index writes.
   These examples add no universal case requirements.
3. **Freeze a complete packet.** Version source corpus and substantive reviewer
   guidance separately. Retain exact source/guidance identities and an evaluator
   key with expected axes, rationale and proportionate outcomes. Keep that key,
   builders, preflight answers and previous results outside reviewer inputs.
   Pre-save readable full prompts, configured settings, output paths and capture
   method. Choose lossless raw-byte artifacts (compressed when useful) separately
   from readable display copies, so display formatting never changes originals.
   Before dispatch, every case has supported ground truth, the complete
   corpus/key is declared, and original outputs can be retained. An unresolved
   invalid control leaves the packet unready; report it instead of freezing a pass.
4. **Collect actual independent judgments.** Use fresh separate assignments with
   the agreed settings and neutral source/contracts/guidance inputs. Keep sibling
   outputs independent until all original reports for that round are preserved.
   Save exact raw reports,
   actual assignment/settings/source/tool records and all outcomes. If actual
   reviewer assignments are unavailable, report that limit; scripts and canned
   findings do not substitute for judgment. Respect stage and side-effect scope.
5. **Adjudicate substantively.** For each expected concern/control, connect the
   contract, observed source evidence, classification, consequence and remedy.
   Explain matches, misses, supported extra concerns, invalid controls, unsupported
   blockers and optional suggestions. Hashes and passing checks establish identity
   or observed behavior separately from design judgment. Preserve differing axes
   and original failed adjudications; append corrections instead of rewriting them.
6. **Correct and report within bounds.** After source or substantive guidance
   correction, identify the new versions and evaluate the complete final declared
   corpus before claiming success; a subset or old clean report cannot transfer.
   Preserve all trials and disclose remaining gaps when authorized scope/resources
   end. Report actual finite cases/repetitions, confounded source/guidance changes
   and unavailable telemetry without general reliability or wording-only causal
   claims. Corpus success does not replace an existing independent whole-ticket
   audit, later source reviews or human acceptance. Development calibration and
   runtime instruction delivery/enforcement require their own actual evidence.
   Distinguish declared snapshot permissions from enforced isolation, and pre-saved
   prompt identity from proven backend delivery; report unavailable telemetry.
