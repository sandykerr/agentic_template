## Findings

### F1 — Blocking: h8 cannot supply the required fourth acceptable control under its frozen contract

**Full key:** `review-ticket-19/spec-01/F1`.

**Governing requirements:** Ticket 19 criterion 1 requires “at least four concern cases and four acceptable controls,” with expectations recorded before evaluation. Criterion 3 requires the evaluator to explain “each expected/observed match and mismatch.” The approved reviewer-evaluation contract requires scoped case/contracts and concrete substantive assessment rather than scoring by counts. h8's own `snapshot/cases/h8/CONTRACT.md:5–6` states: “Consumers receive copied snapshots; caller-owned input dictionaries cannot mutate state.”

**Locations:** `19-evaluation/snapshot/cases/h8/attempt.py:2–4,6–9,16–22`; its unrestricted caller at `caller.py:3–7`; evaluator acceptance at `19-evaluation/results.md:18–21`; published claim/qualification at `docs/agents/reviewer-evaluation.md:16–18,24–34`. The corpus paths are under `.scratch/ticket-harness/evidence/`.

**Evidence:** `__init__` stores `identity` directly and `_transition` stores `revision` directly. The copied dictionaries are shallow, and neither entry validates scalar types. For example, `identity = {'value': 'A'}` and `revision = {'value': 'r1'}` pass construction, submit and complete. Changing either dictionary afterward changes the corresponding values in both owner snapshots without invoking any owner operation. This is demonstrated in [spec-h8-observation.json](/tmp/ticket19-review/spec-h8-observation.json). It uses the exact supplied source and an ordinary dictionary mutation explicitly covered by the contract, not concurrency or an invented crash/failure model.

Both original reports narrow their clean conclusion to immutable domain values and disclose the problem with mutable values. The declaration/contracts do not specify that restriction, and the source/caller does not enforce it. The evaluator's later “Match within ordinary scalar domain values” therefore does not resolve the frozen control's actual promise. An acknowledged limitation is valuable provenance, but cannot make this source satisfy the four-acceptable-control requirement. This is a corpus/adjudication blocker; the four required seeded concern detections remain valid, and I am not retroactively calling h8 a predeclared required concern.

**Consequence:** A defective or unresolved control is counted as the fourth acceptable design, and the published success claim trains later work to set aside an explicit contract using an assumed input domain. Ticket 19's finite required outcome is not fully established even though all hashes and original key findings match.

**Proportionate remedy:** Preserve G1's original declaration, snapshot, raw reports and trial outcome. Append the contract/source mismatch and correct current success summaries. Establish a versioned corpus with an actually acceptable owned-transition control and an explicit input/copying contract; do not silently edit or replace G1. Obtain fresh independent full-corpus final evaluation on the exact declared source/guidance, retaining this trial and any guidance revision. A small fixture correction or explicit, justified input contract is sufficient; no production refactor, generic state machine, runtime backend work or extra test matrix is requested. If the mismatch remains unresolved, leave ticket completion pending. This is within the ticket's authorized evaluation repair scope; a reviewer cannot authorize relaxing an approved requirement or accepting consequential risk.
