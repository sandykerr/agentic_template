## Findings

### F1 — Blocking: deeply nested invalid decision kills the QA owner and leaves a false active-wait observation

**Full key:** `review-ticket-24/spec-01/F1`.

**Contract:** Ticket 24 criterion 2 requires “Missing, unreadable, malformed, mismatched, stale and replayed decisions retain observable waiting/rejection behavior”; criterion 5 preserves “indefinite waits” and status behavior. The approved spec's QA section says malformed approvals cannot promote/unlock later work and “QA waits are indefinite and observable, without repair-budget consumption or failure classification.” No decision-depth bound or narrower accepted-input domain is specified/enforced at the file boundary.

**Source:** `ticket_harness/qa.py:343` parses raw external JSON in `MilestoneReview._consider_decision`; its rejection handler at `qa.py:360` catches only `ValueError` and `GateFailure`. A decoder `RecursionError` escapes `_await_decision`, `_Run.execute` and `__main__.main`, whose handlers also omit it. The same incomplete exception handling existed in baseline `qa.review`; this whole-ticket acceptance finding concerns the now-owned operation and does not misattribute introduction to this refactor.

**Concrete observation:** After the public run reached M1 `awaiting_human_qa`, I wrote a regular `qa-decision.json` containing `"[" * 10000 + "0" + "]" * 10000` (20,001 bytes, a schema-invalid JSON array). The owner exited **1** with `RecursionError: maximum recursion depth exceeded while decoding a JSON array`. The durable record still said `outcome=awaiting_human_qa`, `qa_decision_status=missing`, with **zero** saved QA observations, although the raw observation artifact had been written. Status repeated that stale waiting record. Both refs remained unchanged and later tickets remained pending, so this is loss of waiting/observability/continuability, not unauthorized promotion. Stop then failed because no active owner existed; continue failed because no deliberate checkpoint existed. Merely replacing the malformed decision cannot resume this run.

**Consequence/classification:** A modest malformed decision artifact ends the authorized QA lifecycle and strands completed ticket work in an unsupported interruption while status still advertises a human wait. This defeats an explicit ticket guarantee at the affected review owner; it is blocking even though the weakness was carried from baseline. Existing invalid-decision tests cover syntax, shape/types, duplicate keys, stale content and file shapes but not this decoder failure.

**Proportionate remedy:** Treat `RecursionError` from decision decoding/comparison as an ordinary rejected decision in the review's existing rejection/persistence path. Add one focused regression through the approved public CLI seam demonstrating that a deeply nested invalid artifact records rejection, keeps the owner waiting with unchanged refs/attempts/later tickets, and permits a subsequent correct decision (or deliberate stop). No new checkpoint schema, recovery mechanism, owner or approval authority is required. The repair must receive both original axes and renew the required final-source checks and whole-ticket reviews under the existing workflow.
