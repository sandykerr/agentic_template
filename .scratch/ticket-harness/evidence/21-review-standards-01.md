## Substantive assessment

I applied AGENTS.md, GLOSSARY.md, ADR-0001/0002, the scoped ownership/lifecycle/verification/continuation/refactor contracts in the approved spec, the harness guide/design pointer, project configuration, and `docs/agents/{domain,python-environment,testing,ownership-review,review-records,architecture-checkpoints,reviewer-evaluation,development-efficiency}.md`. The Standards, OOP, codebase-design, and test-strategy skills supplied the design lens. No CODING_STANDARDS.md or CONTRIBUTING.md was found. Tool-enforced style was left to the recorded static checks; smell heuristics were not treated as automatic violations.

**The ticket cycle now owns its decisions through a cohesive interface.** `_run` selects a ready ticket, supplies its verified integration base and concrete existing data, and invokes `_TicketExecution.execute` (`runner.py:410`). It does not set repair variables or decide which rejected revision to reuse. `_TicketExecution` privately retains the fixed original base, repair starting revision, preceding source, current attempt and repair context (`tickets.py:148`). Its ordered execute operation owns fresh implementation, capture, checks, both reviews, candidate verification, expected-old advancement and the bounded retry decision. Removing this owner would put that ordered policy back in its caller. The function's length expresses one cohesive cycle; it is not evidence of divergent responsibilities by itself.

The concrete `_TicketVerification` capability (`runner.py:255`) grants four related effects: durable observation, protected Git operation/worktree destination, runner checking for this ticket, and source validation/retirement of rejected evidence. It fixes the ticket identity privately and derives compatible destinations through the existing naming function. Ticket policy receives neither `_Run` nor the run record/verified registry. The capability preserves checking ownership rather than copying checker policy into ticket code. Its operations add ticket scoping, protection and validation ordering; it is not a setter facade for the runner's data or an extensible callback/framework collection. Passing the existing projection/history/gates privately is compatible with the approved record contract because the workflow reads history/gates and delegates lifecycle writes to `_Attempt`.

**Writers and reference identity remain coherent.** `_Attempt` (`tickets.py:23`) still appends its canonical attempt dictionary, initializes the current-ticket projection, observes source/submission/candidate, attaches an identity-checked human decision, rejects the attempt, and marks completion with gate ranges. Ticket execution invokes those operations; it does not duplicate their field edits. Runner checking appends the actual result to the same canonical gate list, registers that result in `verified`, and supplies the explicitly identified attempt when a validated decision needs attachment (`runner.py:131`). No positional history selection was introduced. Readiness helpers own Pending/Ready initialization and unlock; `_run` owns the active-ticket alias, integration observation, final Blocked/outcome classification and milestone coordination. QA's existing integration-revision write remains limited to milestone promotion. These changed and unchanged writers have distinct responsibilities.

`_TicketExecution` retains the actual lists/projection supplied by `_run`; it creates a shallow mapping only to reorder assignment snapshot names. Snapshot entries are not mutated. The requirement's source is matched against normalized snapshot sources from `inputs.load`, then the active ticket is swapped into `ticket`; checks are selected by that requirement. `agents.assignment` reads captured artifact contents and receives ticket/baseline gates, the fixed base, and the current starting/submitted revision. The new internal constructor is reached from validated loading or a validated deliberate checkpoint, not an unvalidated public input route. Configuration enforces a nonnegative integer repair allowance and finite positive timeouts. No narrower scalar/alias assumption is required to justify a copying guarantee: the existing shared projection/gate identities are intentional; no new deep-copy promise is made.

**Repair and stop precedence is preserved.** `tickets.py:200` allows one initial attempt plus the configured repairs. The fixed `_base` never changes; `repair_start` selects a submitted revision when capture succeeded or the starting revision plus preserved working contents when it did not. Previous worktrees stay intact and each attempt gets a new destination. Failure/rejected revisions are scoped by ticket. The local stage is set before operations and restored to runner observation in the catch, so worktree/merge failures retain their originating stage even though runner checking has its own stage field.

`_Run.check` continues to own timeout category, process/report validation, human-decision versus process-exit/finding precedence, gate registration and source invalidation. Execution environment and integrity failures become nonrepairable; valid human questions attach to the matching attempt and stop before capture/repair. Ordinary repairable failures share the one allowance. Before retry, approved inputs are checked, this ticket's verified references are retired, and remaining baseline/earlier-ticket sources are validated in the original order (`runner.py:302`). Canonical failed evidence remains in gates and artifacts. External integration movement or rejected-worktree HEAD movement stops further repair. Exhaustion and integration failures propagate to `_run`, preserving the existing fail-fast behavior and completed earlier tickets.

**Exact-source success is kept atomic at the observation seam.** Every repair restarts applicable checks and independent reviews. Candidate validation checks the exact base/submission parents, identical reviewed tree and unchanged worktree. After its exact candidate suite, execution validates all approved/verified inputs and advances the integration branch with expected-old update and disabled hooks (`tickets.py:270`, `git.py:93`). Only then does the attempt become Done and execute return the tested revision. `_run` immediately records that returned revision, unlocks dependents and saves the complete observation (`runner.py:423`). There is no external command or intervening save between Done and these integration/unlock observations. A failed ref update cannot return success or unlock work. Later tickets are constructed from this updated verified revision.

**Persistence, restore and invalidation remain compatible.** Domain execution objects are not serialized. `_Run.save` uses the existing atomic JSON replacement; the same existing dictionaries/lists produce the same public records. `qa._persist` exports version-1 checkpoint record/config/verified values; `qa.restore` validates checkpoint, frozen evidence, approved inputs, source worktrees and refs before continuation. `_Run.restore_checks` resolves decoded verified evidence back to canonical `record['gates']` objects (`runner.py:51`), so subsequent invalidation updates durable/status-visible gates. Continuation constructs an execution for later unfinished tickets after the saved QA boundary; completed work is not reconstructed as a new active attempt. Protected operation/check paths still use `records.protect`, preserving snapshots/prior artifacts and diagnostic bytes. The CLI/status reader and external completion-evidence consumer retain their existing contracts.

**Change locality is appropriate.** Adjusting bounded repair decisions would change ticket execution and its CLI scenarios; runner report precedence and record primitives need no mirrored repair logic. Adding a review role would change the ticket cycle plus the existing assignment/report/timeout contract and corresponding behavior tests, with record gates still generic. Neither change requires callers to initialize private execution fields or coordinate transition setters. No inheritance, speculative registry, general state-machine framework or new private testing seam was introduced. The full upstream smell baseline produced no evidence-based finding requiring a remedy.
