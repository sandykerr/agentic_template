# Evidence retention audit — review, evaluation, QA and provenance

Read-only semantic audit, 2026-11-12. Worker: `/root/review_evidence_audit`, requested GPT-6.1 Sol / Medium. This report proposes no deletion and changes no retained evidence, requirements, ticket, source or disposition. Configured model/reasoning is not independent backend telemetry.

## Finding

The retained material is a mixture of original judgments, historical inputs, observed executions, derived indexes and exact copies. Age, a completed review lifecycle, Git tracking and a current clean summary do not establish redundancy. Several superseded passing judgments are uniquely useful evidence of what the process missed. The current M1 blocker and changed-source renewal dependency make a portion of this history directly relevant to unfinished work.

The present approved contract explicitly preserves originals, failed trials, instruction/source identities and append-only history. A human choosing smaller retention is choosing a changed preservation policy, rather than merely applying an existing permission to remove old files. There is no evidence here of authority to discard them.

## Governing retention versus technical necessity

Read [AGENTS.md](../../../../AGENTS.md), [GLOSSARY.md](../../../../GLOSSARY.md), both [ADR-0001](../../../../docs/adr/0001-reusable-harness-and-local-integration.md) and [ADR-0002](../../../../docs/adr/0002-human-qa-gates-feature-promotion.md), [issue conventions](../../../../docs/agents/issue-tracker.md) and the [review contract](../../../../docs/agents/review-records.md). The contract requires unique original report/evidence paths and external digests; verbatim original output when an envelope changes it; failed/rejected attempts; actual instruction/settings identity or disclosed absence; append-only disposition events; and frozen QA evidence. Historical formats/scope must remain historical. The [approved spec](../../spec.md#review-work-findings-and-decisions) requires preserved reports and append-only history; its [evaluation clause](../../spec.md#reviewer-evaluation) explicitly preserves failed trials, misses and guidance revisions. The [M1 definition](../../milestones.md#m1-a-complete-qa-controlled-git-cycle) requires reviewer evaluation, genuine old checkpoint compatibility, cumulative assessment and exact-source QA evidence.

These are current contractual obligations. They do not establish that Python production execution intrinsically needs every development Markdown report or that every historical generated file needs to stay unpacked forever. Conversely, runtime stopped checkpoints and frozen artifacts can be operational inputs to `continue`; their need differs from documentary historical review. A source repository Git object can recover committed bytes only while that object/repository remains available, and does not inherently recover uncommitted snapshots, external temporary fixtures, actual judgments or delivered instructions. No complete Git recoverability/deduplication proof was attempted in this audit.

## Method and limitations

Used shell reads, `rg --files`/targeted searches and tar member listing. Inspected governing contracts, assessment/index/history records, original report content, manifests/results, evaluation outcomes across C1–C5, human QA response/provenance and archive/draft explanatory content. Listed worker archive members, including observer diagnosis/report/source/trace artifacts; did not extract or independently adjudicate every member. No Python, dependency install, tests, new reviewer trial, runtime run, source repair, issue status change or deletion occurred. The scope is semantic sampling and representative reference tracing, not a full physical inventory, hash revalidation of every attachment, comprehensive broken-link audit or runtime reconstruction. Counts/digests and execution results above are attributed to retained records unless stated as direct inspected content. No file has been deemed disposable based on age, tracking status, filename or summary overlap.

A concrete exact-copy candidate differs from all the unique judgments above: [M1 capture](../m1-qa-01/capture.json) assigns caller-index `cli.stdout` and `run.json` the same SHA-256 and 6,221-byte size, and likewise assigns control `cli.stdout` and `run.json` the same SHA-256 and 10,442-byte size. That retained manifest describes duplicated serialized output through two observation paths, whereas `standards-01-original.md` and its envelope have different bytes and purposes. This audit did not independently compare these file bytes; any human-selected physical deduplication should first verify equality and preserve both logical names, original path semantics and external manifest relationships. Archive packing can preserve exact logical records while reducing loose files; a summary cannot preserve an original judgment merely by retaining its hash.

## Lifecycle dependencies for a possible evidence skill

A ticket's terminal authoring status is not a sufficient evidence-expiry condition. This repository separates ticket completion, assessment completion, finding disposition, candidate readiness and milestone acceptance. An evidence policy could name dependencies in a way similar to ticket prerequisites, but humans must decide which dependencies are binding and what minimal artifact satisfies each; this audit makes no such policy change.

Possible skill design inputs are therefore **evidence role**, **exact identity**, **original/derived relationship**, **actual versus synthetic authority**, **current consumers**, **open lifecycle dependencies**, **canonical preserved location** and **explicit human retention rule**. A discard candidate would need a proven satisfied dependency set and a defined acceptable loss, not only an age or `completed`/`accepted` marker. Humans also need to settle whether immutable evidence is preserved in place, moved losslessly with path mapping, or retained through a smaller approved record. Those alternatives differ materially under the current preservation contract. This audit neither authors a skill nor grants any deletion eligibility.
