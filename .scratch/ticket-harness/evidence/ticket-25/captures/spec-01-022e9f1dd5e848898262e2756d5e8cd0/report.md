## Findings

### F1 — Blocking: an identical retry bypasses validation of later registered originals

Full key: **`review-ticket-25/spec-01/F1`**.

Source: `ticket_harness/evidence.py:301-310`, specifically the `return` at line 310 inside the loop. Contract: ticket 25's original-capture/protected-original requirements; `docs/agents/evidence-capture.md:29-32` says registration checks previously registered captures in the artifact and rejects changed/missing originals; the `register` operation's own docstring at line 258 promises rejection of mutation of any registered originals.

Counterexample using accepted public inputs: allocate A and B for ticket 25, write and register one regular original file in each allocation, change B's registered file, and repeat A's identical registration. The loop validates A and returns before inspecting B. In the retained exact-checkpoint probe, that retry exits **0** with empty stderr even though B's recorded SHA256 `c321e97664ec098fdea6c93bf2a3eb6b9f0a97fdfab45059f6fcd8d90468be3c` differs from the observed `62f38c5cbc61bac8126c7ae87ee2cbe78d682c4c6fae60dd8d9a58ea23684e63`. Retrying B as a control exits **1** with `Registered original changed`. Before/after artifact bytes are identical.

The consequence is order-dependent failure detection: the same artifact with a broken registered original produces a successful registration retry for an earlier capture, contrary to the promised original-integrity check. This is not a demand for protection against adversarial simultaneous replacement or for the helper to prevent external mutation. Mutation is already an explicitly supported failure case that registration promises to reject; the existing negative test also mutates a producer file to establish that guarantee. The ordinary retry path skips that check for later entries.

Proportionate remedy: validate identities for every prior capture before any successful idempotent return, then resolve whether the matching existing capture is identical. Add one public-CLI regression for an earlier-capture retry after a later original is changed or missing. Preserve existing original records and review namespaces; no broader refactor or expanded matrix is required.

No optional suggestions are asserted.
