## Ownership and flow

CLI main -> runner.run -> _run -> inputs.load. _Run still creates output/inputs and preserves rejected run output. The loader's docstring makes this filesystem precondition and output separation explicit. Within one call, inputs validates executable commands, computes validated execution defaults and repository path, captures approved bytes/names/hashes, normalizes all tickets, validates the plan and graph, verifies current integrated completion evidence, and establishes executable readiness/prerequisites, first selection and workers. Failure order and actionable diagnostics remain in the same operations; the runner catches failures as invalid-input before worker/baseline/ref advancement.

PreparedInputs is a frozen carrier of already-owned results, with settings separate from requirements/selected/completed IDs/checked plan/worker settings. `settings` contains validated execution defaults/resolved repository and preserves the configuration's path-based ticket/plan selection. No requirements, normalized selection/completion or checked plan is inserted there. execution_config owns the single conversion into the pre-existing runtime/checkpoint mapping: settings plus normalized values and the checked plan/workers when applicable. This is a shallow mapping assembly deliberately preserving the existing shared references between execution config and run record; it adds no defensive-copy promise or mutation-free validation requirement. No external caller fills calculated fields into settings. Future preparation-rule changes remain local to inputs/plans; run callers only consume the finished result/conversion.

All definitions/usages traced: inputs.load has one caller (_run); plans.validate has one caller (inputs.load). Both first-milestone membership and executable required-ticket decisions now use the checked return. All later runtime plan consumers in runner, tickets, agents and qa receive only execution_config's checked plan. Pure parsing, graph checks, role defaults/overrides and transformations remain in their original functions. No configuration framework, adapter hierarchy or test seam added.

Unchanged writers/readers: inputs.configuration initializes execution defaults; load captures files and computes preparation values; plans.validate owns membership, transitive milestone dependency order, roles/defaults and overrides. tickets.initialize/unlock/next_ready consume normalized requirements, selected/completed IDs and checked plan; _TicketExecution and agents.assignment consume checked workers/roles and ticket metadata.
