### Attempt lifecycle, current-ticket projection and callers

Criterion 1 requires existing observations, revisions, changed files and inclusive/exclusive gate ranges, including failure before submission. `tickets.py:24–104` now owns those observations. The owner retains the actual gate list and measures its length at start and terminal transition, preserving the run-wide half-open ranges.

`submit` changes attempt state, submitted revision and changed-file observations, then projects the existing attempt fields into the current ticket. `observe_candidate` and `complete` coordinate their relevant observations. `reject` always writes Rejected, failure and exclusive gate end, including when worktree creation, report validation or another operation fails before capture; it does not require a submitted revision. `repair_start` returns preserved starting/submitted revision, available source and failure observations without deciding whether another attempt is allowed.

The distinct lifecycle projections are deliberate compatibility: a historical attempt becomes Rejected while the ticket retains its prior Running/Verifying observation until a repair starts Running or the run classifies the terminal result Blocked. Failure/gate-end history does not get added to the ticket projection. Source is initially attempt-only, then included by the existing submission projection. This matches the baseline code and the public record vocabulary; making both dictionaries identical would violate compatibility.

Every lifecycle writer in `tickets.execute` now calls these operations.
