**The inspected design satisfies the Standards axis without a blocking finding or optional suggestion.** This conclusion comes from the following ownership and flow trace, independently of the passing suite.

`__main__.main` still resolves the public run/continue paths, prints the returned record and preserves returned codes; status reads `run.json` without starting execution. `runner.run` (446–450) creates fresh output with `exist_ok=False`, retains exclusive directory ownership and calls `_Run(...).execute(config_path)`. `continue_run` (453–460) retains ownership, `qa.restore` validation, separate rejection artifacts and ValueError propagation, then calls the same lifecycle operation without rebuilding configuration or patching fields. Removing `_run` removes the external initialization sequence rather than merely adding another forwarding layer.

`_Run.__init__` (23–47) establishes the existing output directories, fresh or restored durable record and verification/protection state. `execute` (49–178) now owns the decisions previously spread between `_run` and the run object: one prepared-input load, initialization, branch identities, baseline, current-milestone scheduling, continuation setup and terminal classification. Its length reflects one cohesive run operation. A caller does not need to know when to set configuration, approved paths, milestone position or durable lifecycle fields. Splitting this into setters would restore the very ordering knowledge this ticket removes.
