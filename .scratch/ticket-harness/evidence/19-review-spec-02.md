**Full key:** `review-ticket-19/spec-02/F1`. This is distinct from original `review-ticket-19/spec-01/F1`; it is a new b7 control/adjudication concern, not a replacement h8 observation.

**Governing requirements:** Ticket criterion 1 requires “at least four concern cases and four acceptable controls”; criterion 3 requires the declared controls to be acceptable and the evaluator to explain expected/observed matches and mismatches; criterion 4 requires final guidance evaluation on the complete declared corpus after correction. The unchanged b7 contract, `19-evaluation-g4/snapshot/cases/b7/CONTRACT.md:2–5`, says `validate` “returns the resolved root and requested branch” and rejects “an unexpected branch.” It supplies no prohibition on a tag sharing a branch name. Ownership guidance additionally requires an input-domain restriction to have contract or enforced-validation support.

**Source:** `.scratch/ticket-harness/evidence/19-evaluation-g4/snapshot/cases/b7/git_ops.py:11–13`, called through `caller.py:5–12`. The same branch query/comparison is also present in preceding corpus stages. C4 `results.md`'s b7 acceptable-match row and final full-pass paragraph, and `docs/agents/reviewer-evaluation.md`'s current C4-pass claim, rely on a missed control defect.

**Concrete exact-source evidence:** In a disposable clean real Git repository initialized on branch `main`, with one commit and that commit as valid ancestral base, `preflight(repo, 'main', base)` succeeds. Add a tag named `main` without changing worktree or HEAD. `git symbolic-ref HEAD` remains `refs/heads/main`; `git branch --show-current` remains `main`; status is empty; base verification and ancestry both succeed. But `git symbolic-ref --short HEAD` now returns `heads/main`. The validator compares this context-sensitive ref abbreviation with `main` and raises `ValueError('unexpected branch')`. [Minimal committed-source reproduction](/tmp/ticket19-review2/spec-b7-observation.json) records commands/exits/output and exact source hashes. This is an ordinary valid Git state, not shell injection, malformed input, failed command, different branch or exotic filesystem assumption.

Both final reviewers and evaluator accept it clean, so the final required acceptable-control corpus and completion claim remain unsupported.
